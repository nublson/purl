# Folders Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A backend for folders (one optional folder per link), so the user can build Figma-designed screens against real hooks and routes. It covers the data model, domain logic, app/v1/MCP APIs, client hooks, the save-flow filing, and the `/folders/[slug]` route.

**Architecture:** A `Folder` Prisma model and a nullable `Link.folderId`. Domain logic lives in `src/lib/folders.ts` (explicit `userId`, ownership → 404) plus folder-aware functions in `src/lib/links.ts`. Thin route handlers follow the existing `/api/links` patterns. Client hooks in `src/hooks/use-folders.ts` are the contract for the user's screens (spec §6). The folder page reuses `HomeShell` with a `folderId` prop.

**Tech Stack:** Next.js App Router, Prisma/Postgres, Better Auth sessions, Vitest (node env), sonner.

**Spec:** `docs/superpowers/specs/2026-09-30-folders-design.md`

## Global Constraints

- Name: "Folder" everywhere (`Folder`, `folderId`, `/api/folders`, `/folders/[slug]`, MCP `list_folders`).
- A link is in at most one folder. The folder relation uses `onDelete: SetNull`; `Folder.user` uses `onDelete: Cascade`.
- Folder names are trimmed, 1–60 chars, and unique per user **case-insensitively**. Also `@@unique([userId, name])` and `@@unique([userId, slug])`.
- Slug: lowercase, accents stripped, runs of non-`[a-z0-9]` → `-`, trimmed of `-`, max 50 chars. Empty → `folder`. Collisions → `-2`, `-3`, … It is regenerated on rename.
- `MAX_FOLDERS = 100` in `src/lib/limits.ts`.
- Unknown **or another user's** folder → 404 everywhere (never 403).
- Error codes: `NAME_EMPTY`, `NAME_TOO_LONG` (400), `NAME_TAKEN` (409), `LIMIT_REACHED` + `feature: "FOLDER_LIMIT"` (403).
- Error copy, verbatim: "Give your folder a name." / "Keep it under 60 characters." / "You already have a folder with that name." / "You can have up to 100 folders." / "Something went wrong. Try again."
- Success toasts, verbatim: "Folder created", "Folder renamed", "Folder deleted", "Moved to {name}", "Removed from {name}", "Saved to {name}".
- Mutations call `broadcastLinksChanged` (existing; no-op without Supabase).
- HARD RULE: DB commands only against the local Docker DB (`DATABASE_URL=postgresql://purl:purl@127.0.0.1:5432/purl_dev`, container `purl-postgres`; Docker CLI in `~/.docker/bin`). Never against hosted Supabase.
- Lint with `pnpm exec eslint src next.config.ts` (`pnpm lint` also scans stale worktrees). No UI design work: presentational screens are the user's.

## Review Focus

1. **Re-saving an existing URL from `/home` (no `folderId`) must not unfile or move it.** Expect `moved: false` and the folder unchanged. Pinned in Task 3.
2. **Renaming a folder to the same name in different case** (`books` → `Books`) must succeed, not return `NAME_TAKEN` from matching itself. Pinned in Task 2.
3. **A name whose slug is empty or collides after rename** (`"🍣"`, or renaming to a name whose slug matches another folder's): expect `folder`/`-2`, never a unique-constraint 500. Pinned in Task 2.
4. **`/api/links?folderId=<foreign or unknown>`** must be a 404, not an empty list that looks like an empty folder. Pinned in Task 5.
5. **Deleting a folder with `withLinks`** deletes only that folder's links; links in other folders and unfiled links are untouched, and the count returned is accurate. Pinned in Task 2.
