## What is Purl

Read-it-later app: a home for your "pearls". Users save URLs (web, PDF, YouTube, audio); Purl resolves metadata (title, favicon, description, thumbnail) and keeps them in one place. There is no AI layer: the in-app chat and the extraction/embeddings/semantic-search pipeline were removed. `/ai` and `/chat/*` redirect to `/home` via `redirects()` in `next.config.ts`.

No paid plans: every account gets the same **1,000-link cap** (`MAX_SAVED_LINKS` in `src/lib/limits.ts`, enforced by `assertCanSaveLink` in `src/lib/entitlements.ts`; API/MCP return `403` with `code: LIMIT_REACHED`, `feature: SAVE_LIMIT`).

## Architecture

Single Next.js App Router application (not a monorepo).

### Route groups

- `src/app/(public)/` — Marketing site (landing page with Google/GitHub sign-in)
- `src/app/(private)/` — Authenticated app: `/home` (save links), `/folders/[slug]` (one folder's links)
- `src/app/api/` — API routes (links, folders, auth, feedback, user, v1, MCP, pdf-proxy)
- `src/app/sw.ts` — Serwist PWA service worker (compiled to `public/sw.js` on build; **disabled in dev**)
- `src/app/~offline/` — Static offline fallback page
- **Landing page** (`src/app/(public)/page.tsx`, static): pieces in `src/components/landing/` (`LandingHero`, `ProductPreview`, `LandingFooter`, `PearlWord`, `LandingIntro`); no top bar: the pearl logo sits centered above the headline (alt "Purl", no wordmark) and arrives first; the copy lives in `landing-hero.tsx` / `landing-footer.tsx`. The theme follows the system (dark first), with pearl tokens in globals.css (`--pearl-1..4`, `--pearl-glow`; `pearl-text` / `pearl-glow` utilities). The first-visit arrival is CSS only (`landing-arrive` / `landing-rise` / `landing-row` keyframes and the `[data-pearl-word]` sheen, all under `html:not([data-landing-seen])`; reduced motion swaps them for a plain `landing-fade`): `LandingIntro` writes `localStorage["purl:landing-seen"] = "1"` when the sheen ends (or after an 1,800ms fallback), and the inline `LANDING_SEEN_SCRIPT` (`src/lib/landing-intro.ts`, in the root layout's `<head>`, so it runs on every full load) sets `data-landing-seen` on `<html>` before paint on later visits; `LandingIntro`'s `useLayoutEffect` does the same for client navigations (log out → `/`). `both` fill keeps content visible without JS. The product panel is a live, read-only demo of the `@purl` account (`DEMO_USERNAME` in `src/lib/demo-links.ts`): `getDemoFolders` (`src/lib/demo-folders.ts`) reads its **public** folders (in its owner's order) and their latest links, the page revalidates hourly (`revalidate = 3600`; `pnpm dev` renders per request) and on demand: every link/folder write calls `broadcastLinksChanged`, whose deferred task also runs `revalidateLandingDemoFor` (`src/lib/demo-revalidation.ts`: `revalidatePath("/")` when the writer is `@purl`), so the account's changes show on the next visit. With no `purl` user or no public folders, `getDemoFolders` returns null and the page keeps the still `ProductPreview`. `DemoProvider` (`src/components/landing/demo-provider.tsx`) feeds the app's real providers demo data: `FoldersProvider` `offline` (never fetches), `LinkViewProvider` `persist={false}`, `CurrentFolderProvider`/`CurrentUserProvider`, and no `LinksSyncProvider`; `LandingDemo` then draws the app's own header controls (folder menu, share popover, account menu) and `LinkItem`/`LinkCard` by day, list or grid (at most three columns: `DEMO_GRID_COLUMNS` / `DEMO_GRID_FRAME`, passed to `LinkGrid` as `columns`), opening on Reading list. `useIsDemo` (`src/contexts/demo-mode-context.tsx`) switches six components: `FolderSelectDropdown` (folders switch in place, digit keys too, Home/New/Edit/Delete disabled), `FolderSharePopover` (Public on and locked, Copy works), `User` (`@purl`, Settings/Feedback/Log out disabled), `ViewModeMenu` (List/Grid is local state, Folder tags disabled), `LinkItem` and `LinkCard` (links open in a new tab, no selection, menu or read marking). The demo makes no `/api/` requests. e2e: `e2e/landing-demo.spec.ts` (it creates the `purl` user, so local database only). The footer's API, MCP, Privacy and Terms links point to `/` until their pages exist. e2e: `e2e/landing.spec.ts`.

### Save flow

Saving is fully **synchronous**; there is no background processing:

1. `POST /api/links` (or v1 API / MCP `save_link`) → `assertCanSaveLink` → `detectContentType` + `scrapeLinkMetadata`
2. Insert (or refresh, for a duplicate URL) the `Link` row
3. `broadcastLinksChanged` → Supabase Realtime → client refresh

### Folders

- A link belongs to at most one folder: `Folder` model, `Link.folderId` (`onDelete: SetNull`, so deleting a folder unfiles its links unless deleted `withLinks`). Cap: `MAX_FOLDERS = 100` (`src/lib/limits.ts`).
- Routes: `/folders/[slug]` page; `/api/folders` + `/api/folders/[id]` (app) and `/api/v1/folders` + `/api/v1/folders/[id]` (API key; same shapes and errors, `PATCH` update and `DELETE ?withLinks=`); `folderId` on the links endpoints (filter on GET, file on POST — a duplicate URL is moved and the response reports `moved`; `folderId` on app and v1 `PATCH /api/.../links/[id]` moves a link, `null` unfiles it). MCP: `list_folders`, `create_folder`, `update_folder`, `delete_folder` (`deleteLinks` opt-in), `move_link`, plus `folderId` on `save_link` / `list_saved_items`.
- **Bulk move/delete** (the selection bar): `PATCH /api/links/bulk` `{ ids, folderId }` (`null` unfiles) → `{ moved: [{ id, previousFolderId }], notFound }`, and `DELETE /api/links/bulk` `{ ids }` → `{ deleted }`; same on `/api/v1/links/bulk`, plus MCP `move_links`. Ids are deduped, capped at `MAX_BULK_LINK_IDS`, and other users' ids are skipped, not errors (parsing in `src/lib/bulk-links.ts`, writes in `moveLinksToFolder` / `deleteLinksForUser`). Client: `useFolderActions().moveLinks` (one toast, Undo puts each link back in its previous folder) and `deleteLinksWithUndo` (`src/lib/pending-link-deletes.ts`). Selection state lives in `src/lib/link-selection.ts` (`linkSelection.toggle(id, { shiftKey })`, `selectAll`, `clear`, `selectedIds`; `useSelectedLinkIds`, `useIsLinkSelected`); `HomeShell` registers the visible links in display order and clears the selection when the folder changes. UI: hovering a row (or long-pressing on touch) shows its checkbox; while anything is selected every row shows one, a row click toggles it (Shift for a range) and row menus hide. `LinkSelectionBar` (`src/components/link-selection-bar.tsx`) floats at the bottom: count (clears), Select all, Move (folders, "Remove from …", "New folder…" which creates quietly via `createFolder(input, { quiet: true })` and moves into it; icon-only below 23rem, where the full bar doesn't fit), Mark as read / unread, Delete; shortcuts in `src/lib/link-selection-shortcuts.ts` (Esc, ⌘/Ctrl+A, Delete/Backspace, M, R) shown in tooltips with `Kbd`. The bar is one Tab stop (roving tabindex; arrows, Home, End). On touch screens (`pointer-coarse:`) its controls are 40px with a 2px invisible extension (44px targets; Move goes icon-only on touch phones so it fits), while mouse users keep the 32px bar. Select all is a checkbox whose label always reads "Select all" (the box shows checked / mixed); the count's name starts with its visible text ("2 selected, clear selection").
- Each folder has an optional `emoji` (exactly one emoji grapheme, validated by `normalizeFolderEmoji`; invalid → 400 `INVALID_EMOJI`). `FolderSummary.emoji` is always set: the stored value or `DEFAULT_FOLDER_EMOJI` (🦪). Each folder also has an optional `description` (trimmed, ≤160 chars, `MAX_FOLDER_DESCRIPTION_LENGTH`; too long → 400 `INVALID_DESCRIPTION`), `null` in `FolderSummary` when unset. Create takes `{ name, emoji?, description? }`; `updateFolder` / `PATCH /api/folders/[id]` take `{ name?, emoji?, description? }` (`null` clears `emoji`/`description`).
- **Reading state:** `Link.readAt` (null = unread). Opening a link from its row (click, middle-click, or the menu's "Open in new tab") marks it read; the row menu toggles "Mark as read" / "Mark as unread", and the selection bar's button (or `R`) marks the selection read, or unread once every selected link is read (the selection stays). Client: `src/lib/link-read-state.ts` (`setLinksRead` shows the change at once, sends one request at a time in order with `keepalive`, rolls back with a toast on failure; `HomeShell`'s reload settles confirmed changes).

- **Folder order:** `Folder.position` (ascending, ties by name; the migration seeded it from each user's A–Z order) is the order of the folder menu, the digit shortcuts, `GET /api/folders`, v1 and MCP `list_folders`, and the landing demo. API: `PUT /api/folders/order` and `PUT /api/v1/folders/order` `{ ids }` → `{ folders }` (v1 CORS allows `PUT`); MCP `reorder_folders`. **UI, in the folder menu itself** (no dialog): each folder row has a grip (`FolderGrip`); with a mouse or keyboard it replaces the emoji on the highlighted row (Radix `data-highlighted`: hover or arrow keys), drawn at 20px so its lines span the emoji's ink width, on touch screens (`pointer-coarse:`) it's always shown at the row's end (32px drawn, 44px wide to the touch, not taller: rows are 33px apart) and the shortcut slot is hidden; on touch Home's check sits in that grip column (Home has no grip), lined up with the grips, and folder rows reserve that slot until the drag code loads (no reflow). Truncated names carry a `title`. Dragging uses Motion `Reorder` in `src/components/folder-menu-reorder.tsx` (rows make way with a 250ms unbouncy spring, not Motion's 450ms default; `MotionConfig reducedMotion="user"`, so with reduced motion they jump instead of sliding), loaded when the pointer nears the trigger or the menu opens (rows show without grips until then); the list auto-scrolls near its edges, a dragged row is bounded by the list (`dragConstraints`, `dragElastic` 0.1 past its edges) and springs back near-critically damped (`bounceStiffness` 600, `bounceDamping` 50), the order changes live and saves once on the drop, and a drag's release never activates anything: the menu content swallows clicks (`onClickCapture`) until just after it, since Radix clicks whichever item (a folder, Home, New/Edit/Delete) is under a pointerup that started elsewhere. The grip's `mousedown` is prevented: rows are links, and the browser's native link drag would cancel the pointer events. ⌥↑ / ⌥↓ (Alt) moves the highlighted row; focus stays on it (also when the draggable rows replace the plain ones), and every move (or "already first/last"; an identical message is cleared and re-set so it's read again) is announced in a live region **inside** the menu (Radix hides the rest of the page from assistive tech while a menu is open). Only with 2+ folders; never in the demo. Client: `byPosition` / `saveFolderOrder` (`src/lib/folder-order.ts`) via `useFolderActions().reorderFolders`: optimistic; saves go one at a time in order and only the latest one's response touches the list; `FoldersProvider.holdFetches` drops background folder fetches while a save is in flight and refetches once nothing is held; the PUT times out after 15s; a failure restores the previous order, reloads and toasts ("Your folders changed elsewhere" for `INVALID_ORDER`). The e2e `seed.folder` puts each folder last. e2e: `e2e/reorder-folders.spec.ts` (drags move one animation frame per step: WebKit can otherwise get the whole drag between two frames).
- **Folder shortcuts:** digit keys switch folders anywhere in the app (`1` = Home, then `2`–`9` and `0` for the first nine folders in menu order, i.e. the user's order), not while typing or with a dialog/menu open (the folder menu handles them itself). Rules in `src/lib/folder-shortcuts.ts`; the menu shows each row's key in a `Kbd` (the current row shows its check instead). Shared guards: `isTypingTarget` / `isOverlayOpen` in `src/lib/keyboard.ts`.
- The folder dialog's emoji picker is Frimousse (`src/components/ui/emoji-picker.tsx`); its emoji data loads from the jsDelivr CDN at runtime. Its footer's ✋ button opens the six skin tones (`useSkinTone`); the chosen tone applies to the grid and is remembered in `localStorage` (`purl:emoji-skin-tone`). Toned emoji are still one grapheme, so `normalizeFolderEmoji` accepts them. New folders suggest an emoji from the name until one is picked (`suggestFolderEmoji` in `src/lib/emoji-suggestion.ts`: a curated topic → emoji list, first matching word, simple plural/-ing forms; no network, no AI); the suggestion shows on the button, labelled "(suggested)", and is saved on create. Editing never suggests.
- Client folder state comes only from `FoldersProvider` (`src/contexts/folders-context.tsx`) via `src/hooks/use-folders.ts` (`useFolders`, `useCurrentFolder`, `useFolderActions`). The current folder is resolved by the folder page (server-side, handed down through `CurrentFolderProvider`), so saves there file by folder id.

### Static pages (Notion CMS)

Content for static pages (Privacy, Terms, API, MCP…) lives in Notion, the same setup as nublson.com. `src/lib/notion.ts` (server-only, `@notionhq/client`) reads one database, the data source `NOTION_PAGES_DATA_SOURCE_ID`: each row is a page, with `Name` (title), `slug` (text, lowercase, the URL segment), `description` (text, meta description) and `state` (select: `planned`, `writing`, `published`; only `published` shows); the database is "Purl Pages" in the nublson workspace (data source `244b1726-8ab3-83c3-9388-87a7a5748b73`); the row's body is the content. `getPublishedPages()` lists them (no content), `getPageBySlug(slug)` returns one with its blocks (`NotionBlock`: children nested up to 5 levels, 5 fetches at a time; child pages/databases aren't followed), null when missing or unpublished. Both are `unstable_cache`d under the `notion` tag for an hour; `POST /api/notion/revalidate` expires the tag at once. It's called by the Notion integration's webhook subscription (page events; the free plan has no database automations), each event signed with `X-Notion-Signature` (`sha256=` HMAC of the raw body keyed by the subscription's verification token, `NOTION_WEBHOOK_SECRET`; creating the subscription POSTs `{ verification_token }` unsigned, which the route logs and answers 200 without revalidating), or by hand with `NOTION_REVALIDATION_SECRET` as `?secret=` or `Authorization: Bearer`. Event bodies are ignored: any event refreshes every page. Without `NOTION_ACCESS_TOKEN` / `NOTION_PAGES_DATA_SOURCE_ID` every read returns nothing (no throw), so local dev and builds work without Notion. Notion-hosted file URLs (uploaded images) expire after ~1h, so rendering them needs a proxy like nublson.com's `/api/notion-image`.

### Authentication & routing

- **Better Auth** (`src/lib/auth.ts`) — sign-in is Google/GitHub OAuth only (Apple is enabled when its env vars exist), sessions stored in Postgres
- **`src/proxy.ts`** — Next.js middleware: rate limiting, and an **optimistic** sign-in check (a Better Auth session cookie is present; no database work, as Next.js and Better Auth recommend). Without the cookie, private pages redirect to `/`. Only `/` (which sends signed-in users to `/home`) validates the session there, so a stale cookie can't loop `/` ↔ `/home`; `@/lib/auth` is imported dynamically for that (and for API-key rate limiting), keeping Better Auth and Prisma out of the proxy's cold start (it was ~1.2s p75 cold). API routes (`/api/*`) pass through to their handlers.
- **The real checks are server-side, where the data is:** the `(app)` layout and `/oauth/consent` `redirect("/")` without `getSessionUser()`, and every API route checks its own session or key (`getSessionUser`, `getBrowserSessionUserId`, `auth.api.getSession`, MCP/v1 auth) and answers 401. A new private page or API route must do the same: the proxy no longer guards it. e2e: `e2e/auth-gate.spec.ts`.
- **OAuth discovery** (`/.well-known/oauth-authorization-server`, `/.well-known/oauth-protected-resource`, Better Auth's MCP metadata) is the same for every caller (Better Auth builds it from `BETTER_AUTH_URL`, not the request; `src/app/.well-known/oauth-discovery.test.ts` checks every host gets the same document), so both routes are wrapped in `withCdnCache` (`src/lib/cdn-cache.ts`: `public, s-maxage=3600, stale-while-revalidate=86400`, errors uncached) and the CDN answers MCP clients' lookups. Never use `withCdnCache` on a route that reads a session or API key.
- Every user has a unique `username` (rules in `src/lib/usernames.ts`), changed only via `PATCH /api/user/username`

## Testing

Vitest, node environment. Test files: `src/**/*.test.ts`.

`src/vitest.setup.ts` handles three important mocks that must not be bypassed:
- Sets a dummy `DATABASE_URL` so Prisma modules load without a real DB
- Mocks `server-only` so server modules can be imported in tests
- Mocks `undici` fetch to respect `globalThis.fetch` stubs
- Mocks `node:dns/promises` to return a public IP (passes SSRF guards)

Test patterns: mock `globalThis.fetch`, mock Prisma client calls, mock Supabase clients. Tests focus on business logic — avoid shallow UI-only wrappers.

### End-to-end (Playwright)

`e2e/*.spec.ts`, run with `pnpm test:e2e` in Chromium and WebKit (not in CI); install the browsers once with `pnpm exec playwright install chromium webkit`. It reuses a running `pnpm dev` on :3000 or starts one, and loads `.env` + `.env.local` like the app. Each worker first checks the app accepts its test session, so a reused server running with a different database or auth secret fails fast with a clear error. The save test fetches `https://example.com`, so it needs network access.

- **Local database only.** `playwright.config.ts` refuses to run unless `DATABASE_URL` points at localhost: the tests create and delete users, folders and links.
- **Sign-in:** OAuth can't be automated, so `e2e/fixtures.ts` gives each worker its own `@purl.test` user (reserved domain, deleted afterwards) and signs the browser in with session cookies minted by a test-only Better Auth instance with the `testUtils` plugin (`e2e/support/auth.ts`, same DB, secret and base URL as the app). Nothing test-only ships in `src/lib/auth.ts`. Opt out per test with `test.use({ signedIn: false })`.
- **Seeding** goes through plain `pg` (`e2e/support/db.ts`), not the generated Prisma client, which Playwright's CommonJS loader can't load. Use the `seed` fixture (`seed.link`, `seed.folder`); every test starts with no links or folders.
- **Hydration:** pages are server-rendered, so a control can be clicked before React hydrates it. Call `waitForHydration(page, selector)` before interacting with client-only controls (menus, dialogs).

## Key gotchas

- **`pnpm dev` does not run `prisma generate`** — run it manually if `src/generated/prisma` is missing.
- **`pnpm build` does** run `prisma generate` automatically.
- **ESLint rule:** no namespace imports from `reicon-react` or `@radix-ui/*` — use named imports only.
- **Icons are Reicon (`reicon-react`), not Lucide.** `components.json` still says `"iconLibrary": "lucide"` (the shadcn CLI has no Reicon option), so `shadcn add` writes `lucide-react` imports. Swap each for its Reicon equivalent (`CheckIcon` → `Check`, `XIcon` → `X`, `ChevronDownIcon` → `ChevronDown`, `Loader2Icon` → `Loader`; browse names at reicon.dev) and don't install `lucide-react`; ESLint rejects `lucide-react` imports.
- **Sign-in is Google/GitHub only** (Apple is enabled when its env vars exist); for local dev, create OAuth apps with localhost callbacks `http://localhost:3000/api/auth/callback/{google,github}`.
- **Usage UI**: the link count vs. the cap is in **Settings → Usage**, not `/home`. See `src/app/(private)/(app)/layout.tsx`, `src/lib/usage-summary.ts`, `src/components/dialog-settings.tsx`.
- **On-screen keyboard (iOS)**: iOS doesn't shrink the page for the keyboard; it scrolls the whole view up to reveal a focused field, which pushed the header off-screen. `KeyboardInset` (`src/components/keyboard-inset.tsx`, in the root layout) reads `visualViewport` and sets `--keyboard-inset` (layout height minus visible height; not minus `offsetTop`, which iOS sets to the same pan), sizes `<html>` to the visible area while it's open (`html[data-keyboard-open]`, `!important` to beat `h-full`) and scrolls the pan back. Things pinned to the bottom use `var(--bottom-inset)` (`max(safe area, keyboard)`, globals.css) instead of `env(safe-area-inset-bottom)`. The domain chip and ⌃ ⌄ ✓ bar above the keyboard are Safari's own UI and can't be removed from the page. Test it in the iOS Simulator's Safari at `localhost:3000` (Next's dev server blocks its scripts for `127.0.0.1`).
- **iOS taps and hover timers**: a tap sends iOS Safari's emulated `mouseover` first, and Safari holds the tap's click until any short timer started then has run (it watches whether the page reacts to the "hover"). Row hover previews start their timers from `onPointerEnter`, skipping `pointerType === "touch"` (a mouse or hovering pen still previews), never `onMouseEnter`: the 400ms preview delay made every row tap on phones ~400ms late.
- **First-load bundle**: the emoji picker (Frimousse), the Add links picker (cmdk) and Motion's animation features load on demand (`next/dynamic` / `LazyMotion`, prefetched after hydration); `open-graph-scraper` is imported inside `scrapeLinkMetadata`, so pages listing links don't load it on a cold start. Keep heavy, rarely used modules out of Home's static imports.
- **Refresh on return**: `HomeShell` reloads the list and folder counts when the tab becomes visible after `RETURN_REFRESH_AFTER_MS` (30s) hidden, since an installed iOS app's Realtime connection can drop while suspended. There is no pull-to-refresh.
- **Serwist (PWA)**: service worker is disabled in `pnpm dev`. Use `pnpm build && pnpm start` to test install/offline behavior.
- **Supabase variables use the Vercel integration's names:** `SUPABASE_URL`, `SUPABASE_ANON_KEY` (legacy anon JWT), `SUPABASE_SECRET_KEY` (server-only; `SUPABASE_SERVICE_ROLE_KEY` is the fallback). The browser gets only the URL and anon key, for Realtime, through `next.config.ts` `env` (the integration doesn't prefix them `NEXT_PUBLIC_`); never add a secret there. Local `.env.local` needs the same names.
- **All user-supplied URLs must go through `safeFetch`** — never raw `fetch` — to prevent SSRF.
- **Outbound proxy on Vercel**: optional `SAFE_OUTBOUND_HTTP_PROXY` for metadata fetches — see [`docs/production-outbound-proxy.md`](docs/production-outbound-proxy.md).

## CI

PRs target `develop` (default) then `main` for releases. Pipeline: setup → Prisma → lint + typecheck (parallel) → tests + build (parallel). Releases are manual (`workflow_dispatch`) and merge `develop` into `main`.

The release workflow runs `prisma migrate deploy` against production (secret `PRODUCTION_DATABASE_URL`, the Supabase **session pooler** URL on port 5432) after the build and before it publishes the `release/build-validation` status that gates the Vercel deploy. A failed migration fails the gate, so the new code never ships against an old schema. Keep migrations backward-compatible (additive), since the previous deploy keeps serving until the new one is live. Pending migrations that drop or delete data (`DROP`, `DELETE FROM`, `TRUNCATE`, column type changes) block the release unless it's started with `allow_destructive_migrations` (back up production first).

**Dev (dev.purl.live, the Vercel Preview of `develop`) has its own database:** the `purl-dev` Supabase project, through Preview-scoped `DATABASE_URL`, `SUPABASE_URL`, `SUPABASE_ANON_KEY`, `SUPABASE_SECRET_KEY` and `BETTER_AUTH_SECRET` (never production's; production's Supabase variables come from Supabase's Vercel integration, Production only). The build runs `scripts/migrate-preview-db.mjs` before `next build`: on a `develop` Preview build only, it runs `prisma migrate deploy` against that database and enables row-level security on every `public` table (no policies; Prisma connects as the owner), so a merged migration reaches dev with its code. Production is never migrated by the build. PR previews share dev's database without migrating it, so a PR that adds a migration works on its preview only after it merges.
