## What is Purl

A calm place to save and share the links you find: a home for your "pearls". Users save URLs (web, PDF, YouTube, audio, images, video) and upload files (images, video, audio); Purl resolves metadata (title, favicon, description, thumbnail) and keeps them in one place. There is no AI layer: the in-app chat and the extraction/embeddings/semantic-search pipeline were removed. `/ai` and `/chat/*` redirect to `/home` via `redirects()` in `next.config.ts`.

No paid plans: every account gets the same **1,000-link cap** (`MAX_SAVED_LINKS` in `src/lib/limits.ts`, enforced by `assertCanSaveLink` in `src/lib/entitlements.ts`; API/MCP return `403` with `code: LIMIT_REACHED`, `feature: SAVE_LIMIT`), and the same **250 MB of storage** for uploaded files (`MAX_UPLOAD_BYTES_PER_ACCOUNT`, read through `getStorageCapForUser` and enforced by `assertCanStore` and `insertWithinSaveLimit`'s `bytes`; `feature: STORAGE_LIMIT`), at most 25 MB a file (`MAX_UPLOAD_FILE_BYTES`). See Media and uploads under Folders.

## Architecture

Single Next.js App Router application (not a monorepo).

- `src/app/(public)/` — Marketing site (landing page with Google/GitHub sign-in)
- `src/app/(private)/` — Authenticated app: `/home` (save links), `/folders/[slug]` (one folder's links)
- `src/app/api/` — API routes (links, folders, auth, feedback, user, v1, MCP, pdf-proxy)
- `src/app/sw.ts` — Serwist PWA service worker (compiled to `public/sw.js` on build; **disabled in dev**)

The hero is left-aligned on the product panel's left edge (the same `md:px-[6%]` as `ProductFrame`, against the same parent): the pearl and a "Purl" wordmark (`BrandMark`, shared with the static pages; the pearl is decorative) arrive first, then a quiet 46px headline (36px on phones), the sub-headline, and the sign-in buttons; the demo is the big moment. The demo makes no `/api/` requests. e2e: `e2e/landing-demo.spec.ts` (it creates the `purl` user, so local database only). The footer's API, MCP, Privacy and Terms links go to the static pages (see Static pages). e2e: `e2e/landing.spec.ts`. **Preview image:** `src/app/opengraph-image.tsx` (the site's, inherited by any page without its own; rebuilt daily) and each static page's `opengraph-image.tsx` (its Notion title and description, refreshed with the page) all draw `renderSiteOgImage` (`src/components/site-og-image.tsx`): the Purl mark, headline and line on the left, the site's host (`BASE_URL`) at the bottom; the site's alone (`showcase`) adds six hand-picked links (`SHOWCASE_LINKS`, fixed, not an account's) as grid cards fading in on the right, and the static pages' are text only. Thumbnails and favicons go through `fetchImageAsDataUrl`, so favicons must be PNG/JPEG (the renderer can't read .ico or SVG: use the site's `apple-icon.png` or Google's favicon service), and the renderer ignores `em` letter-spacing (use px). The palette, pearl/globe marks and Inter loader are shared with the shared folder's image in `src/lib/og-theme.ts`. The proxy lets `/opengraph-image*` and `<static page>/opengraph-image*` through (Next adds a hash to nested ones).

### Save flow

Saving is fully **synchronous**; there is no background processing:

1. `POST /api/links` (or v1 API / MCP `save_link`) → `assertCanSaveLink` → `detectContentType` + `scrapeLinkMetadata`
2. Insert (or refresh, for a duplicate URL) the `Link` row. A duplicate deleted while its metadata was resolving (the app sends a delete 5 s after the row leaves the list, so delete-then-resave gets here; Prisma `P2025` on the update) is inserted fresh with the metadata already resolved, never a 500.
3. `broadcastLinksChanged` → Supabase Realtime → client refresh

Uploaded files take their own path, `POST /api/links { upload }` after the browser has put the file in Blob, also synchronous and ending in `broadcastLinksChanged` (see Media and uploads under Folders).

### Folders

- A link belongs to at most one folder: `Folder` model, `Link.folderId` (`onDelete: SetNull`, so deleting a folder unfiles its links unless deleted `withLinks`). Cap: `MAX_FOLDERS = 100` (`src/lib/limits.ts`).
- Routes: `/folders/[slug]` page; `/api/folders` + `/api/folders/[id]` (app) and `/api/v1/folders` + `/api/v1/folders/[id]` (API key; same shapes and errors, `PATCH` update and `DELETE ?withLinks=`); `folderId` on the links endpoints (filter on GET, file on POST — a duplicate URL is moved and the response reports `moved`; `folderId` on app and v1 `PATCH /api/.../links/[id]` moves a link, `null` unfiles it). MCP: `list_folders`, `create_folder`, `update_folder`, `delete_folder` (`deleteLinks` opt-in), `delete_link`, `move_link`, plus `folderId` on `save_link` / `list_saved_items`. MCP also publishes read-only **resources** for Claude's Add menu: `purl://links` ("🏠 All links") and `purl://folders/{id}` (one per folder, listed in menu order), each read as Markdown links grouped by UTC day with descriptions cut to 200 characters (`src/lib/mcp-resources.ts`, `registerPurlResources`).
- **Bulk move/delete** (the selection bar): `PATCH /api/links/bulk` `{ ids, folderId }` (`null` unfiles) → `{ moved: [{ id, previousFolderId }], notFound }`, and `DELETE /api/links/bulk` `{ ids }` → `{ deleted }`; same on `/api/v1/links/bulk`, plus MCP `move_links`. Ids are deduped, capped at `MAX_BULK_LINK_IDS`, and other users' ids are skipped, not errors (parsing in `src/lib/bulk-links.ts`, writes in `moveLinksToFolder` / `deleteLinksForUser`). Client: `useFolderActions().moveLinks` (one toast, Undo puts each link back in its previous folder) and `deleteLinksWithUndo` (`src/lib/pending-link-deletes.ts`). Selection state lives in `src/lib/link-selection.ts` (`linkSelection.toggle(id, { shiftKey })`, `selectAll`, `clear`, `selectedIds`; `useSelectedLinkIds`, `useIsLinkSelected`); `HomeShell` registers the visible links in display order and clears the selection when the folder changes. A search keeps the selection: selected links it hides stay selected, counted and included in Move/Delete (`selectedIds` lists the shown ones first), Select all adds the results and unchecking it unselects only them (`useAreAllShownSelected`, `unselectShown`); `setSelectableLinks(ids, { complete })` drops links missing from the list only when it's the whole list (no search, every page loaded), and `HomeShell` removes deleted or moved-out links as they go; a reload after the data changed (the sync version, the return refresh) runs with `reconcile`, keeping only selected links the fresh list has (`linkSelection.retain`), since a link a search hid may have been deleted or moved out elsewhere; `settled` keeps the list's cursor with its groups, so "complete" never mixes two answers. UI: hovering a row (or long-pressing on touch) shows its checkbox; while anything is selected every row shows one, a row click toggles it (Shift for a range) and row menus hide. `LinkSelectionBar` (`src/components/link-selection-bar.tsx`) floats at the bottom: count (clears), Select all, Move (folders, "Remove from …", "New folder…" which creates quietly via `createFolder(input, { quiet: true })` and moves into it; icon-only below 23rem, where the full bar doesn't fit), Delete; shortcuts in `src/lib/link-selection-shortcuts.ts` (Esc, ⌘/Ctrl+A, Delete/Backspace, M) shown in tooltips with `Kbd`. The bar is one Tab stop (roving tabindex; arrows, Home, End). On touch screens (`pointer-coarse:`) its controls are 40px with a 2px invisible extension (44px targets; Move goes icon-only on touch phones so it fits), while mouse users keep the 32px bar. Select all is a checkbox whose label always reads "Select all" (the box shows checked / mixed); the count's name starts with its visible text ("2 selected, clear selection").
- Each folder has an optional `emoji` (exactly one emoji grapheme, validated by `normalizeFolderEmoji`; invalid → 400 `INVALID_EMOJI`). `FolderSummary.emoji` is always set: the stored value or `DEFAULT_FOLDER_EMOJI` (🦪). - **Uploads: the pipeline.** Files go from the browser straight to Vercel Blob and then become pearls (`@vercel/blob`'s own calls are the one exception to `safeFetch`). Client, `uploadFiles` (`src/lib/save-uploads.ts`): `validateUploadFile` (`src/lib/uploads/validate.ts`) takes the reported type when it's in `UPLOAD_MIME_TYPES` (`src/lib/uploads/mime.ts`), else the extension's (`.m4a` → `audio/x-m4a`), else toasts "photo.heic isn't a supported file" (an empty file too), and "clip.mov is over 25 MB" over `MAX_UPLOAD_FILE_BYTES`; the rest upload `MAX_CONCURRENT_UPLOADS` (3) at a time, in order, from one pool shared by every batch. Per file: `makePreview` (`src/lib/uploads/preview.ts`, browser only, never throws: the pixel size, a video's or audio's length in whole seconds (`roundDuration`: rounded, at least 1, null when unknown; the row accepts only a positive integer), and a WebP preview with its long side at most 1,280px at quality 0.82; a video's frame at 0.1s; a GIF gets none, its original stays animated) → a client token, which the client asks for itself by POSTing Blob's `blob.generate-client-token` event to `POST /api/uploads/token` (`clientPayload { kind: "file", mimeType, size }`) → `put()` (`@vercel/blob/client`) with that token, `multipart`, to `users/<userId>/<uuid>/<sanitizeUploadName>` (progress capped at 99 until the pearl lands) → the same for the preview at `…/preview.webp` (`kind: "preview"`; if that fails the pearl is saved without one) → `POST /api/links { upload: { url, previewUrl, name, mimeType, width, height, duration }, folderId? }`. The token route (`issueUploadToken` in `src/lib/upload-token.ts`, over Blob's `handleUpload` with no `onUploadCompleted` and no `callbackUrl`, so Blob never calls back; the client sends no `callbackUrl` and the route rebuilds the event from `pathname`, `clientPayload` and `multipart` alone, so no client can add one) accepts only a path of exactly `users/<userId>/<id>/<name>` (`isOwnBlobPathname` in `src/lib/uploads/blob-url.ts`); a file must have an allowed type, be at most 25 MB and pass `assertCanSaveLink` and `assertCanStore`; a preview must be `image/webp`, named `preview…` and at most `MAX_UPLOAD_PREVIEW_BYTES` (2 MB), with no entitlement check. The token allows exactly that type and size, `addRandomSuffix`, for 10 minutes. Refusals are `400 { error, code }` (`UploadRejectedError`: `INVALID_PAYLOAD`, `INVALID_PATH`, `UNSUPPORTED_TYPE`, `FILE_TOO_LARGE`; a body that isn't a token event is `INVALID_BODY`) or the 403 limit. The row request (`createUploadForUser` in `src/lib/uploads.ts`; `InvalidUploadError` is `400 INVALID_UPLOAD`, `{ url, upload }` together a 400) trusts nothing the client says: both URLs must be Blob URLs in the user's own prefix, the preview in the file's directory, named `preview…` and not the file itself. `head()`, with Purl's token, must answer with exactly the URLs sent, which pins Purl's store (another store's blob fails); `BlobNotFoundError` is 400 "Upload not found", any other `head` error a 500 the client may retry. Then a blob uploaded more than `UPLOAD_ROW_WINDOW_MS` (30 minutes) ago is refused ("Upload expired"), Blob's type must be allowed and match the client's, the preview must be WebP and at most 2 MB, and the size above 0. The row goes in through `insertWithinSaveLimit` with `bytes: head.size` (link cap and storage under one lock) and `reuse` by `fileKey`, so a retried request returns the same pearl, while two uploads of one file are two pearls. The row: `url` the file, `thumbnail` the preview, `fileKey` and `fileSize` from Blob's `head`, the title the file name without its extension (`titleFromFileName`; control characters dropped, as in `mediaTitleFromUrl`, so a NUL never reaches the insert), the domain `BASE_URL`'s host (`purl.live`, with a warning, when it's unset), favicon `/icon.png`, no description. Any failure after the heads deletes both blobs before rethrowing (`discardBlobs`, skipped when a saved row already uses them).
- **Upload limits.** `MAX_UPLOAD_FILE_BYTES` (25 MB a file), `MAX_UPLOAD_BYTES_PER_ACCOUNT` (250 MB, the sum of `Link.fileSize`: `getStorageUsedForUser`; the cap is read through `getStorageCapForUser`, flat today, so a per-account cap needs no call-site change), `MAX_UPLOAD_PREVIEW_BYTES` (2 MB; previews aren't counted). `StorageLimitError` ("Your 250 MB of storage is full. Delete files you no longer need to upload more.") and `SaveLimitError` both extend `LimitError`, which `POST /api/links`, the token route and MCP `save_link` catch: `403 { error, code: "LIMIT_REACHED", feature }`, `feature` `SAVE_LIMIT` or `STORAGE_LIMIT` (v1 still catches only `SaveLimitError`; it takes no uploads). The media viewer has no zoom of its own, and the slide is `touch-none` for the drag (the class is ours: Motion writes no `touch-action` with `dragListener={false}`, and without it the browser's pan and pinch cancel the swipe), so a pinch on the media doesn't zoom on touch (the browser's keyboard zoom still works); it has no actions or details, and `?pearl=` links share the page's own preview image. Embeds ("Show live" iframes for pages, the `embed` / `frameable` columns) are a later plan; `linkKind` already answers `embed`, but nothing sets it and it draws as a page.

### Importing links

Settings → Import (`?settings=import` opens it; `SettingsImport` in `src/components/settings-import.tsx`) brings in a bookmarks file. Formats, detected by `detectFormat` (`src/lib/import/`): a browser bookmarks export (Netscape HTML; folders are the nested `<H3>` names joined with ` / `, minus the browser's top-level root folder (Bookmarks bar, Other bookmarks, …), so links directly in a root folder go to Home), a Raindrop CSV and a Pocket CSV (`title,url,time_added,tags,status`; no folders). **Raindrop, from a real export:** the full backup has a `folder` column holding `Parent / Child` paths, where `Unsorted` means no folder; a single-collection export has no `folder` column at all, so its links go to Home (the preview says so). The HTML and Pocket parsers are built from the formats' shapes, not verified against real files.

**Client flow:** the file is read in the browser (max 5 MB, `MAX_IMPORT_FILE_BYTES`, checked before reading), `parseImportFile` returns `{ format, items, skipped, folders }` (items newest first; a parser throw counts as an unrecognized file), the preview's room line is only an estimate (the server skips saved links before the cap; Import is disabled with no room left), then `runImport` (`src/lib/import/run-import.ts`) POSTs the **whole file** (titles cut to 500) in chunks of `MAX_IMPORT_CHUNK` (200) one after another to `POST /api/links/import`, summing the answers, and stops on `limitReached`, abort or an error; links left unsent after `limitReached` count as over the limit in the summary (`runDoneSummary`). Wording for the preview and the done screen lives in `src/lib/import/import-summary.ts` (`Imported 300 links`, then `Created 12 folders.` and the lines that apply). States: idle (choose or drop a file), preview (focus moves to its heading; Import, Choose another file), importing (progress bar), done (View links, Import another file), error (`role="alert"`: unrecognized, over 5 MB, empty, or a failed request with **Try again**, which resumes after the chunks already answered). Closing the dialog aborts the run; chunks already sent stay saved. Two clicks on Import in one frame start one run (`stateRef`). While the tab is mounted, `window` `dragover`/`drop` listeners cancel every file drag, so a stray drop never opens the file and leaves the app; a drop on the tab's content takes the file in idle, preview and error (replacing the one shown), not while importing or once done.

**Endpoint** (`src/app/api/links/import/route.ts`, `importLinksForUser` in `src/lib/import-links.ts`): checks the session before reading the body; body rules in `src/lib/import-body.ts`; rate-limited in the proxy (`POST /api/links/import`, per IP). Per chunk, in one transaction (`timeout` 30 s, `maxWait` 10 s: Prisma's 5 s default can't fit a chunk creating ~100 folders; the route exports `maxDuration = 60` so the function outlives it) holding both advisory locks, always the folder lock first and then the links lock: validate each link (http(s) URL, title, date, folder name; bad ones count as `invalid`), skip duplicates by `linkUrlKey` (against the account's links and earlier links in the chunk; an existing link is left as it is, never refreshed), cut what exceeds the cap (`overLimit`, `limitReached: true`; the server alone applies the cap, after dedupe, in the file's newest-first order), match folders case-insensitively against existing ones and create the missing ones with `createFolderInTx` (a `suggestFolderEmoji` emoji) while under `MAX_FOLDERS` (the rest go to Home: `unfiledForFolderLimit`), then one `createMany` with `createdAt` from the file (so links sit under their original dates), the domain's default favicon, a content type guessed from the URL (`guessContentType`) and `needsMetadata: true`. No network at import time. Response: `{ imported, duplicates, invalid, overLimit, foldersCreated, unfiledForFolderLimit, limitReached }` (`foldersCreated` is the folders made, not the folders used); `broadcastLinksChanged` runs once per chunk that imported anything.

**Filling in details:** `Link.needsMetadata` marks imported links. A Vercel cron (`vercel.json`, `* * * * *`) calls `GET /api/cron/enrich-links` with `Authorization: Bearer $CRON_SECRET` (set `CRON_SECRET` in Vercel **Production**; without it the route answers 503, a wrong header 401). `enrichFlaggedLinks` (`src/lib/enrich-links.ts`) claims up to 20 flagged links, newest first, with `UPDATE … WHERE id IN (SELECT … FOR UPDATE SKIP LOCKED) RETURNING`, clearing the flag at claim time, so it is at-most-once: overlapping runs never share a link and a failed lookup isn't retried (the link stays as imported). It resolves 5 at a time (`maxDuration` 120). A lookup gets 20 s, then its requests are **aborted**: an `AbortSignal` is threaded through `resolveLinkFromUrl` → `scrapeLinkMetadata` / `detectContentType` → `safeFetch` (each request combines it with its own timeout via `timeoutSignal`, `src/utils/abort-signal.ts`), and the pool slot waits up to 2 s for them to unwind, so no more than 5 are really in flight; a timed-out lookup always counts as failed, even if the abort made a scraper fall back to defaults. It writes by id **and URL** (a link re-pointed meanwhile is left alone) in one transaction per link, never touching `createdAt`, and lets edits made while it waited win: favicon, domain and content type always; description and thumbnail only where still null; the title only when the claimed one was a fallback (empty, the URL or the domain) and the stored title still equals it (compare-and-set). Crons run only in production, so in dev trigger it by hand: `curl -H "Authorization: Bearer $CRON_SECRET" http://localhost:3000/api/cron/enrich-links`. If you check a migration for drift (Prisma 7.5): `pnpm prisma migrate diff --from-config-datasource --to-schema prisma/schema.prisma --exit-code`.

**e2e:** `e2e/import.spec.ts` with made-up fixtures in `e2e/fixtures/import/` (one per format); no network needed. The cron test calls the route with `CRON_SECRET` and is skipped without it, so the git-ignored `.env.e2e` needs `CRON_SECRET=e2e-cron-secret`.

### Static pages (Notion CMS)

Content for static pages (Privacy, Terms, API, MCP…) lives in Notion, the same setup as nublson.com. `src/lib/notion.ts` (server-only, `@notionhq/client`) reads one database, the data source `NOTION_PAGES_DATA_SOURCE_ID`: each row is a page, with `Name` (title), `slug` (text, lowercase, the URL segment), `description` (text, meta description) and `state` (select: `planned`, `writing`, `published`; only `published` shows); the database is "Purl Pages" in the nublson workspace (data source `244b1726-8ab3-83c3-9388-87a7a5748b73`); the row's body is the content. `getPublishedPages()` lists them (no content), `getPageBySlug(slug)` returns one with its blocks (slugs match case-insensitively, in code: Notion's `rich_text equals` is case-sensitive) (`NotionBlock`: children nested up to 5 levels, 5 fetches at a time; child pages/databases aren't followed), null when missing or unpublished. Both are `unstable_cache`d under the `notion` tag for an hour; `POST /api/notion/revalidate` expires the tag at once. It's called by the Notion integration's webhook subscription (page events; the free plan has no database automations), each event signed with `X-Notion-Signature` (`sha256=` HMAC of the raw body keyed by the subscription's verification token, `NOTION_WEBHOOK_SECRET`; creating the subscription POSTs `{ verification_token }`, which the route logs before any signature check (signed or not; only a printable, space-free token up to 256 chars) and answers 200 without revalidating; rejected signed events log why), or by hand with `NOTION_REVALIDATION_SECRET` as `?secret=` or `Authorization: Bearer`. Event bodies are ignored: any event refreshes every page. Without `NOTION_ACCESS_TOKEN` / `NOTION_PAGES_DATA_SOURCE_ID` every read returns nothing (no throw), so local dev and builds work without Notion. There is no image proxy: Notion-hosted file URLs (uploaded images) expire after ~1h, so only **linked** (`external`) images render and uploaded ones are skipped with a `console.warn` (`Static page "<slug>": skipped uploaded image <block id>; link images instead`). Images for these pages go under `public/pages/` (the directory doesn't exist yet) and are linked in Notion as `https://purl.live/pages/<name>`.

The pages: `STATIC_PAGES` (`src/lib/static-pages.ts`, plain data) maps each Notion slug to its path and footer label: `/privacy`, `/terms`, `/support`, `/docs/api`, `/docs/mcp` (API and MCP sit under `/docs` because `/api` is the API routes' namespace). `/support` is the Chrome Web Store's support URL: its Notion body is the extension help and FAQ, and `StaticPage`'s `intro` slot (between the Updated line and the body) holds a code-rendered contact card (`SupportContact`, `src/components/support-contact.tsx`) whose address is `getSupportEmail()` (`src/lib/support-email.ts`: the first plain address in `FEEDBACK_TO_EMAIL`, the in-app feedback inbox, read when the page is built or revalidated; none → the card points at Feedback and GitHub issues instead). Each is a small `src/app/(public)/<path>/page.tsx` (`force-static`, `revalidate = 3600`; the webhook's tag expiry refreshes it sooner) rendering `StaticPage` (`src/components/static-page.tsx`): the `BrandMark` (`src/components/brand-mark.tsx`: pearl and "Purl" wordmark, shared with the landing hero) as a link to `/` (accessible name "Purl, home"; a signed-in reader lands on `/home` through the redirect), the title as the page's only `h1`, the description, `Updated October 3, 2026` (`formatUpdatedDate` in `src/utils/formatter.ts`, UTC, in a `<time>` from the row's `last_edited_time`), the Notion content via `NotionBlocks` and the landing page's `LandingFooter` (`currentPath` marks the page's own link with `aria-current="page"`, `text-foreground` and `font-medium`; a prop, not `usePathname`, so the pages stay static; its "@nublson" link goes to `NUBLSON_URL` when it's an `https:` URL, else GitHub: `src/lib/author-url.ts`); the mark, title, description, Updated line and Notion content share one centered `max-w-[68ch]` column (`COLUMN`, on the landing demo's axis), text left-aligned, every block sharing its edge, while the footer keeps the landing layout; metadata from `title`/`description` (plus canonical, Open Graph and Twitter), `notFound()` when the row is missing or not `published`. The content renderer is `src/components/notion-blocks/` (server components; `NotionBlocks` groups list runs with `group-blocks.ts`, dispatches on `block.type` and recurses into `children`, with one `createRenderContext` per page: the slug, the Notion-id → path map from `getPublishedPages()` and a heading slugger). Supported: paragraph, headings, quote, callout, toggle (`<details>`), bulleted/numbered lists and to-dos, code, image, video, bookmark/embed/link_preview, table, divider, columns, synced_block, and `link_to_page` for a `STATIC_PAGES` row; everything else (child_page, child_database, pdf, file, audio, breadcrumb, table_of_contents…) renders nothing (a dev-only `console.warn` per unknown type). Notion heading_1/2/3 render as `h2`/`h3`/`h4`, and each gets an `id` and a `#` link ("Link to section: <heading>") from `src/lib/heading-slugs.ts` (`slugify`, `createSlugger` de-duplicates `-2`, `-3`). Links go through `classifyNotionLink` (`src/lib/notion-links.ts`): a Notion page URL of a published `STATIC_PAGES` row, `/…`, `#…` and `purl.live` and its subdomains (`*.purl.live`) URLs (as path + search + hash) open in the same tab, other `http(s):` in a new tab (`noopener noreferrer`), `mailto:` in the same tab, anything else is plain text. Notion writes in-text links to workspace pages root-relative (`/<id>`, `/Title-<id>?pvs=4`); those, `notion.so` / `*.notion.site` links and `notion.com` links (page mentions come back as `app.notion.com/p/<id>`) map to the static page's path when the id is a published row, and any other Notion page renders as plain text (visitors can't open it). Videos: YouTube becomes a `youtube-nocookie.com` embed (`getYouTubeEmbedUrl`; the production CSP's `frame-src` allows `https://www.youtube-nocookie.com`, in `src/lib/csp-header.ts`), other URLs and bookmarks are plain links. Code blocks are highlighted on the server by `src/lib/code-highlight.ts` (shiki's fine-grained core with the JavaScript regex engine, `github-light`/`github-dark`, `defaultColor: false`, so tokens carry `--shiki-light`/`--shiki-dark`, which the `.shiki span` rules in globals.css pick per theme; the frame is ours: `bg-muted border rounded-lg`; the literal language list must match `HIGHLIGHT_LANGUAGES` in `src/lib/code-languages.ts`, unknown languages and failures render plain) and `CopyCodeButton` copies the raw code ("Copy" → "Copied" for 2s, no toast). e2e: `e2e/static-pages.spec.ts` (skipped without `NOTION_ACCESS_TOKEN`). A failed Notion read is a 404 only at build time; at runtime it throws so ISR keeps the last good page. The proxy lets every `STATIC_PAGES` path through without a session, and the landing footer links to them. To add a page: a row in Notion, an entry in `STATIC_PAGES`, and its `page.tsx`.

### Authentication & routing

- **Better Auth** (`src/lib/auth.ts`) — sign-in is Google/GitHub OAuth only (Apple is enabled when its env vars exist), sessions stored in Postgres
- **`src/proxy.ts`** — Next.js middleware: rate limiting, and an **optimistic** sign-in check (a Better Auth session cookie is present; no database work, as Next.js and Better Auth recommend). Without the cookie, private pages redirect to `/`. Only `/` (which sends signed-in users to `/home`) validates the session there, so a stale cookie can't loop `/` ↔ `/home`; `@/lib/auth` is imported dynamically for that (and for API-key rate limiting), keeping Better Auth and Prisma out of the proxy's cold start (it was ~1.2s p75 cold). API routes (`/api/*`) pass through to their handlers.
- **The real checks are server-side, where the data is:** the `(app)` layout and `/oauth/consent` `redirect("/")` without `getSessionUser()`, and every API route checks its own session or key (`getSessionUser`, `getBrowserSessionUserId`, `auth.api.getSession`, MCP/v1 auth) and answers 401. A new private page or API route must do the same: the proxy no longer guards it. e2e: `e2e/auth-gate.spec.ts`.
- **OAuth discovery** (`/.well-known/oauth-authorization-server`, `/.well-known/oauth-protected-resource`, Better Auth's MCP metadata) is the same for every caller (Better Auth builds it from `BETTER_AUTH_URL`, not the request; `src/app/.well-known/oauth-discovery.test.ts` checks every host gets the same document), so both routes are wrapped in `withCdnCache` (`src/lib/cdn-cache.ts`: `public, s-maxage=3600, stale-while-revalidate=86400`, errors uncached) and the CDN answers MCP clients' lookups. Never use `withCdnCache` on a route that reads a session or API key.
- **Save-only OAuth tokens (`links:save`):** a third-party site (the registered public client `nublson-com`, from a migration; redirects `https://nublson.com/purl/callback` and the localhost one) and the browser extension (`purl-extension-chrome` / `purl-extension-safari`, `EXTENSION_CLIENT_IDS`, redirect `/extension/connected`; see Browser extension) can get a token that can only save links. The scope is `SAVE_SCOPE` in `src/lib/oauth-scopes.ts`, advertised in discovery and accepted by the OAuth plugin. Guards: MCP rejects these tokens (`verifyToken` returns `undefined`, so `/api/mcp` answers 401); `POST /api/v1/links/save` is the one endpoint they open and takes a Bearer token only (no cookie or API key); `GET /api/v1/links` and the rest stay cookie/API-key. `src/lib/oauth-route.ts` wraps `src/app/api/auth/[...all]/route.ts`: the `SAVE_ONLY_CLIENT_IDS` (the portfolio and both extension clients) may request only `links:save` + `offline_access` (anything else, or no scope, is a plain 400), and any authorize request with `links:save` must send an S256 `code_challenge` (else a plain 400) and is forced to `prompt=consent`, because Better Auth only consents on that and only checks PKCE when a challenge is sent; the token endpoint answers CORS (preflight 204, `Access-Control-Allow-Origin` echoed, never credentials) for any browser extension origin (`chrome-extension://…`, `safari-web-extension://…`: ids differ per install, and without it Safari hides the answer from an extension that wasn't granted access to Purl's site, so a refresh reads as a network failure) and for exact origins in `OAUTH_CORS_ORIGINS` (comma-separated; unset = none), so `OAUTH_CORS_ORIGINS=https://nublson.com` must be set in Vercel Production (and the dev Preview if the portfolio uses it) or the browser's token exchange/refresh fail CORS. Denying consent redirects with `error=access_denied` but no `state` (Better Auth), so the portfolio must handle an error callback without `state`. The refresh grant works with `client_id` alone but does not rotate or invalidate earlier tokens (no reuse detection); disconnecting in Settings → Connected apps (`revokeConnectedApp`) deletes them all. e2e proof was manual against the local database (no spec: OAuth sign-in can't be automated). **Signing out of Purl revokes only the save-only clients' connections** (`revokeSaveOnlyAppsOnSignOut` in `src/lib/auth-hooks.ts`, a Better Auth `hooks.before` on `/sign-out` in `auth.ts`: `revokeConnectedApp(userId, clientId)` for each of `SAVE_ONLY_CLIENT_IDS` deletes its tokens and consent while the session is still readable; a failure is logged per client and never blocks the sign-out), so the portfolio's or extension's next save gets a 401 and runs the connect flow, which asks for a sign-in; other connected apps (Claude and other MCP clients) are untouched.
- Every user has a unique `username` (rules in `src/lib/usernames.ts`), changed only via `PATCH /api/user/username`

## Key gotchas

- **`pnpm dev` does not run `prisma generate`** — run it manually if `src/generated/prisma` is missing.
- **`pnpm build` does** run `prisma generate` automatically.
- **ESLint rule:** no namespace imports from `reicon-react` or `@radix-ui/*` — use named imports only.
- **Icons are Reicon (`reicon-react`), not Lucide.** `components.json` still says `"iconLibrary": "lucide"` (the shadcn CLI has no Reicon option), so `shadcn add` writes `lucide-react` imports. Swap each for its Reicon equivalent (`CheckIcon` → `Check`, `XIcon` → `X`, `ChevronDownIcon` → `ChevronDown`, `Loader2Icon` → `Loader`; browse names at reicon.dev) and don't install `lucide-react`; ESLint rejects `lucide-react` imports.
- **Sign-in is Google/GitHub only** (Apple is enabled when its env vars exist); for local dev, create OAuth apps with localhost callbacks `http://localhost:3000/api/auth/callback/{google,github}`.
- **Usage UI**: the link count vs. the cap is in **Settings → Usage**, not `/home`. See `src/app/(private)/(app)/layout.tsx`, `src/lib/usage-summary.ts`, `src/components/dialog-settings.tsx`.
- **On-screen keyboard (iOS)**: iOS doesn't shrink the page for the keyboard; it scrolls the whole view up to reveal a focused field, which pushed the header off-screen. `KeyboardInset` (`src/components/keyboard-inset.tsx`, in the root layout) reads `visualViewport` and sets `--keyboard-inset` (layout height minus visible height; not minus `offsetTop`, which iOS sets to the same pan), sizes `<html>` to the visible area while it's open (`html[data-keyboard-open]`, `!important` to beat `h-full`) and scrolls the pan back. Things pinned to the bottom use `var(--bottom-inset)` (`max(safe area, keyboard)`, globals.css) instead of `env(safe-area-inset-bottom)`. The domain chip and ⌃ ⌄ ✓ bar above the keyboard are Safari's own UI and can't be removed from the page. Test it in the iOS Simulator's Safari at `localhost:3000` (Next's dev server blocks its scripts for `127.0.0.1`).
- **iOS taps and hover timers**: a tap sends iOS Safari's emulated `mouseover` first, and Safari holds the tap's click until any short timer started then has run (it watches whether the page reacts to the "hover"). Row hover previews start their timers from `onPointerEnter`, skipping `pointerType === "touch"` (a mouse or hovering pen still previews), never `onMouseEnter`: the 400ms preview delay made every row tap on phones ~400ms late.
- **First-load bundle**: the emoji picker (Frimousse), the Add links picker (cmdk) and Motion's animation features load on demand (`next/dynamic` / `LazyMotion`, prefetched after hydration), and the media viewer (Cambio) once a page has a media pearl (`MediaViewerLazy`); `open-graph-scraper` is imported inside `scrapeLinkMetadata`, so pages listing links don't load it on a cold start. Keep heavy, rarely used modules out of Home's static imports.
- **Refresh on return**: `HomeShell` reloads the list and folder counts when the tab becomes visible after `RETURN_REFRESH_AFTER_MS` (30s) hidden, since an installed iOS app's Realtime connection can drop while suspended. There is no pull-to-refresh.
- **SEO and agent discovery** (isitagentready.com scored purl.live 33 before this): `robots.txt` is a route handler (`src/app/robots.txt/route.ts`, `buildRobotsTxt` in `src/lib/robots-txt.ts`) because Next's robots metadata can't write the `Content-Signal` line (`ai-train=no, search=yes, ai-input=yes`: the owner's policy, change `CONTENT_SIGNAL` to change it). The sitemap lists `/` and every `STATIC_PAGES` path. `public/llms.txt` describes the product (facts only; keep it in step with the landing copy). The home page has a canonical, an absolute title and `SoftwareApplication` JSON-LD. `src/lib/agent-discovery.ts` builds `/.well-known/api-catalog` (RFC 9727) and `/.well-known/mcp/server-card.json` (draft SEP-1649; the MCP endpoint is `/api/mcp`, no tool list in the card so it can't drift) and the home page's `Link` header (`next.config.ts`; it imports these by relative path because the config can't resolve `@/`). **Markdown for agents:** `GET` of `/` or a `STATIC_PAGES` path with `Accept: text/markdown` is rewritten by `src/proxy.ts` to `/api/markdown/<key>` (`src/lib/markdown-negotiation.ts`: `home` or the static page's slug), which fetches the page's own HTML and converts its `<main>` with Turndown (`src/lib/html-to-markdown.ts`); those pages send `Vary: Accept`. Pattern borrowed from nublson.com's proxy.
- **Serwist (PWA)**: service worker is disabled in `pnpm dev`. Use `pnpm build && pnpm start` to test install/offline behavior.
- **Browser extension** (`extension/`: its own npm project, Manifest V3; the Chrome Web Store listing is built from it): `npm ci && npm run build` makes `dist/` and `purl-extension.zip` (both gitignored), and the Store only accepts an upload whose `version` in `public/manifest.json` is higher than the last. **Publishing is automatic:** `.github/workflows/auto-bump-versions.yml` raises that `version` on `develop` when a push changes `extension/` (tests, `scripts/` and `.env.example` don't count; the same workflow bumps `server.json` for MCP changes): `type!:` commit subjects → major, `feat:` → minor, else patch, and a version you already changed in the push is left alone. Each Release dispatches `.github/workflows/publish-extension.yml` on `main`, which builds, uploads and submits it for review through the Chrome Web Store API v2 (skipping when the version isn't newer than the store's published or submitted one). Auth is keyless: GitHub OIDC → Google Workload Identity Federation (provider limited to `nublson/purl` on `refs/heads/main`) → the service account linked under the developer dashboard's Account; secrets `GCP_WORKLOAD_IDENTITY_PROVIDER`, `GCP_SERVICE_ACCOUNT`, `PUBLISHER_ID`, `EXTENSION_ID`. It can also be run by hand from the Actions tab (on `main`). If the listing's visibility is changed in the dashboard, publish once by hand before the API can publish again. A production build always talks to `https://purl.live` and fails on any other `VITE_PURL_URL` (empty counts as unset); local development is `npm run dev` (`--mode development`) with `VITE_PURL_URL=http://localhost:3000` in `.env.development`, which adds that origin to the dev manifest's host permissions and names it "Purl (dev)". Minification stays off: `showToast` is serialized with `.toString()` into the page and must stay self-contained. Clicking the icon saves the tab's address (`http(s)` only) with `POST /api/v1/links/save` and a save-only OAuth token (`links:save`), not the session cookie: Safari sends no cookies with an extension's requests (findings in `plans/safari-extension-spike.md`). The result is a toast in the page, or, where the browser won't run scripts (its own pages, some stores), a ✓ / ! badge on the icon with the message as its tooltip, so a missing toast never stops a save. **Connecting:** with no token (or one Purl refuses after a refresh, e.g. after signing out of Purl, which revokes it), it opens `/api/auth/mcp/authorize` in a new tab (S256 PKCE, `state`) as its own client, `purl-extension-safari` when `chrome.runtime.getURL` is `safari-web-extension:` else `purl-extension-chrome` (one per browser, so Settings → Connected apps shows "Purl Safari Extension" / "Purl Chrome Extension"), and remembers the page (`chrome.storage.session`, since the browser can stop the worker during sign-in; 10-minute expiry, one pending save, cleared when the tab closes). The user signs in if needed and allows it; Purl redirects the tab to `/extension/connected` (a public page that never reads the code), where `tabs.onUpdated` takes the code (state checked; a denial has `error` and no `state`), closes the tab, refocuses the original, exchanges the code at `/api/auth/mcp/token` and saves. Tokens live in `chrome.storage.local` and are refreshed a minute before expiry or once on a 401. No `identity` API (Safari lacks `launchWebAuthFlow`). Dev host permissions are portless (`http://localhost/*`): Safari ignores patterns with a port. In Safari, develop with Settings → Developer → Allow unsigned extensions → Add Temporary Extension… on `extension/dist` (both reset when Safari quits). Connecting needs access to Purl's site (the extension reads the connect tab's address): Chrome grants the manifest's host permissions at install, Safari asks per site, so the click calls `chrome.permissions.request` before any `await` (Safari refuses it outside the gesture) and, refused, toasts "Allow Purl to access its site to connect" instead of opening the tab; saving and refreshing don't need it. The icons (`public/icons/icon{16,32,48,128}.png`) are the site's pearl alone on a transparent background (not the black app tile), with a hairline edge so it reads on a light toolbar; regenerate them from `public/logo.svg` with `node extension/scripts/make-icons.mjs` from the repo root (it uses the root's sharp). Tests: `extension/src/background.test.ts` (run by the root `pnpm test`, with `chrome` and `fetch` stubbed); `npm run typecheck` in `extension/`. **Safari:** `extension/safari/Purl/` is the Xcode wrapper app (macOS + iOS, bundle id `live.purl.Purl`); it references `extension/dist/` rather than copying it, so build the extension first. Its app icons come from the same `make-icons.mjs`. `publish-safari-extension.yml` (App Store Connect upload) exists but isn't dispatched until its secrets are set; see `plans/safari-extension-distribution.md`.
- **Supabase variables use the Vercel integration's names:** `SUPABASE_URL`, `SUPABASE_ANON_KEY` (legacy anon JWT), `SUPABASE_SECRET_KEY` (server-only; `SUPABASE_SERVICE_ROLE_KEY` is the fallback). The browser gets only the URL and anon key, for Realtime, through `next.config.ts` `env` (the integration doesn't prefix them `NEXT_PUBLIC_`); never add a secret there. Local `.env.local` needs the same names.
- **All user-supplied URLs must go through `safeFetch`** — never raw `fetch` — to prevent SSRF.
- **Outbound proxy on Vercel**: optional `SAFE_OUTBOUND_HTTP_PROXY` for metadata fetches — see [`docs/production-outbound-proxy.md`](docs/production-outbound-proxy.md). When the proxy itself fails (a refused CONNECT tunnel, any status, or the proxy unreachable: connect timeout, refused, not in DNS; `describeHttpProxyHopFailure`), `safeFetch` logs it and retries once with direct egress, but only after the 10 s connect timeout, so a dead proxy still makes every save slow: remove the variable rather than leave a broken proxy in place. A scrape that falls back to the bare domain logs why (`[scrapeLinkMetadata] <domain>: falling back …`, with the Undici cause chain), so check the runtime logs before guessing.

## CI

PRs target `develop` (default) then `main` for releases. Pipeline: setup → Prisma → lint + typecheck (parallel) → tests + build (parallel). Releases are manual (`workflow_dispatch`) and merge `develop` into `main`.

The release workflow runs `prisma migrate deploy` against production (secret `PRODUCTION_DATABASE_URL`, the Supabase **session pooler** URL on port 5432) after the build and before it publishes the `release/build-validation` status that gates the Vercel deploy. A failed migration fails the gate, so the new code never ships against an old schema. Keep migrations backward-compatible (additive), since the previous deploy keeps serving until the new one is live. Pending migrations that drop or delete data (`DROP`, `DELETE FROM`, `TRUNCATE`, column type changes) block the release unless it's started with `allow_destructive_migrations` (back up production first).

**Dev (dev.purl.live, the Vercel Preview of `develop`) has its own database:** the `purl-dev` Supabase project, through Preview-scoped `DATABASE_URL`, `SUPABASE_URL`, `SUPABASE_ANON_KEY`, `SUPABASE_SECRET_KEY` and `BETTER_AUTH_SECRET` (never production's; production's Supabase variables come from Supabase's Vercel integration, Production only). The build runs `scripts/migrate-preview-db.mjs` before `next build`: on a `develop` Preview build only, it runs `prisma migrate deploy` against that database and enables row-level security on every `public` table (no policies; Prisma connects as the owner), so a merged migration reaches dev with its code. Production is never migrated by the build. PR previews share dev's database without migrating it, so a PR that adds a migration works on its preview only after it merges.
